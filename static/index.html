Overview

EqlipZ Pay is risk and trust middleware for digital payments, built to mitigate settlement risk for Razorpay Route and AI agent protocols (AP2, UCP, MCP). It sits between a payment authorization and Razorpay's settlement rails.

Instead of forcing a binary approve/decline decision when the system is unsure, it holds the money for a short, bounded window (max 48h) and uses a Conformal Risk Engine to provide mathematically guaranteed bounds on fraud probability.

Get started by interacting with the /v1/risk/evaluate endpoint to score mock transactions, or point your Razorpay Webhooks to /webhooks/razorpay to process live payments.

Core Concepts

Conformal Prediction

Traditional ML outputs a single point estimate (e.g. 84% fraud probability). Conformal prediction wraps this output in a set of labels (e.g. {FRAUD, BENIGN}) that contains the true label with a strict statistical guarantee (e.g. 90% confidence), regardless of data distribution. If the model is uncertain, it outputs a multi-class set, which our Decision Router interprets as a HOLD.

Semantic Entailment

An AI Agent might construct a cryptographically perfectly valid transaction that entirely ignores the user's instructions (e.g., buying a $2000 Macbook instead of a $200 Chromebook). The Semantic Engine uses an LLM to compare the user_intent against the executed cart to detect budget violations, category mismatches, and prompt injections.

Continuous Calibration

When Razorpay disputes are won or lost, or when held funds are released by a human reviewer, the real-world outcome is fed back into the Calibration Loop. This dynamically updates the Conformal Engine's thresholds, allowing it to adapt to changing fraud patterns without retraining the underlying model.

POST /v1/risk/evaluate

Overview and Business Logic

The /v1/risk/evaluate endpoint is the core algorithmic heart of EqlipZ Pay. Unlike traditional payment gateways that rely on static rules or black-box ML models outputting a single probability score, this endpoint utilizes a combination of Conformal Risk Prediction and Semantic Entailment to evaluate transactions with strict mathematical guarantees.

This API is designed to intercept a payment before it is fully captured by the settlement rails. By passing the transaction details and (if applicable) the AI agent's cart context to this endpoint, the system calculates a guaranteed prediction set.

  • For Human Transactions: The system relies solely on the Conformal Risk Engine to detect anomalies based on amount, frequency, and custom metadata.
  • For AI Agent Transactions: The system invokes an LLM-backed Semantic Engine to verify that the items added to the cart cryptographically match the human's original prompt.

Request Payload Details

{
  "transaction": {
    "amount": 250.50,
    "is_international": false,
    "extra_features": {"device_id": "mob_123"}
  },
  "source": "AGENT_MCP",
  "user_intent": "Please buy a high-quality mechanical keyboard under $300.",
  "cart": [
    {"name": "Keychron Q1 Pro", "price": 199.00, "quantity": 1}
  ]
}
  • transaction: The core financial object. The amount drives the conformal risk calculation. You can optionally pass is_international or arbitrary keys via extra_features.
  • source: Dictates the evaluation pipeline. Valid values: HUMAN, AGENT_MCP (Model Context Protocol), AGENT_AP2, or AGENT_UCP.
  • user_intent: (Required for Agents) The exact, unaltered natural language prompt provided by the human user.
  • cart: (Required for Agents) An array of JSON objects representing the items the agent is attempting to purchase on behalf of the user.

Response Payload Details

The response dictates the immediate action your integration should take. The system employs a Decision Router to map the prediction sets to discrete financial actions. 

{
  "decision": "HOLD",
  "risk_score": 0.71,
  "intent_alignment": 0.43,
  "prediction_set": ["BENIGN", "FRAUD"],
  "reason_codes": ["intent_mismatch", "conformal_uncertainty"],
  "audit_id": "aud_12345abcde"
}
  • decision: The final routed action.
    • RELEASE: Clear to capture.
    • HOLD: The prediction set was uncertain. Route to Escrow for 48 hours.
    • REFUSE: Hard fraud detected. Reverse or void the authorization.
  • prediction_set: A conformal array guaranteeing the true outcome (e.g. ["BENIGN", "FRAUD"] means the model is uncertain).
  • intent_alignment: A float between 0 and 1 indicating how well the agent's cart matches the user's instructions. A score below 0.6 triggers a HOLD.

WEBHOOK /webhooks/razorpay

Overview and Integration Flow

The Razorpay Webhook endpoint allows EqlipZ Pay to operate entirely asynchronously as a passive listener, reacting to real-time events broadcast by Razorpay's infrastructure.

By configuring Razorpay to point to this endpoint, EqlipZ Pay will listen specifically for payment.authorized and payment.captured events. Upon receipt, the webhook handler extracts the payment metadata, passes it through the Conformal Risk Kernel, and automatically uses the Route Transfer Client to execute an escrow hold or immediate release based on the decision.

Security and Authentication

  • HMAC Signature Verification: All incoming webhook POST requests must include the x-razorpay-signature header.
  • Validation Process: EqlipZ Pay computes a SHA256 HMAC of the raw request body using your configured RAZORPAY_WEBHOOK_SECRET and compares it to the signature header.
  • Rejection: Any request missing the header or containing an invalid signature is immediately rejected with a 401 Unauthorized status to prevent malicious spoofing.

Idempotency and Concurrency

  • Duplicate Event Prevention: Razorpay guarantees at-least-once delivery, meaning you may receive the same webhook multiple times.
  • In-Memory Cache: The listener maintains a processed_payments set. If an event ID is already present, it returns a 200 OK immediately without re-triggering the Risk Engine or executing a duplicate Route Transfer.

GET /api/transactions

Overview

Fetches the recent transaction ledger for the web dashboard. The Decision Router stores a volatile in-memory log of every transaction evaluated by the Risk Engine. This endpoint paginates and retrieves that log for the real-time Transactions feed.

Query Parameters

  • filter (optional): A string to filter the ledger by decision outcome. Valid values are all, RELEASE, HOLD, or REFUSE. If omitted, defaults to all.

Response Payload Details

Returns a JSON array of transaction objects containing exact timestamps and reason codes.

[
  {
    "payment_id": "pay_OXYZ123456",
    "amount": 250.50,
    "source": "AGENT_MCP",
    "decision": "HOLD",
    "reason_codes": ["unusual_transaction", "intent_mismatch"],
    "timestamp": "2026-08-29T10:00:00Z"
  }
]

GET /api/risk-log

Overview

Provides a real-time stream of diagnostic logs directly from the Risk Kernel's internal decision tree. This is highly useful for debugging why a specific transaction was held or refused.

Log Contents

  • Semantic Details: Outputs the LLM reasoning if an agent's cart violates the user's instructions (e.g. "Detected 0.42 intent mismatch due to budget violation").
  • Threshold Boundaries: Logs the exact Conformal Alpha value and the resulting prediction set (e.g. "Set [BENIGN, FRAUD] resulted in HOLD").
  • Fallback Mechanics: Logs warnings when features are missing and the system safely defaults to mean imputation.

GET /api/evaluation

Overview

Returns the strict mathematical evaluation metrics calculated during the model's offline calibration phase. EqlipZ Pay generates a static evaluation_results.json artifact when trained against historical datasets (e.g. ULB Credit Card Fraud).

Key Metrics Returned

  • Empirical Coverage: The actual percentage of transactions where the true label fell within the generated prediction set (should hover near the 90% target).
  • Precision & Recall: Standard binary classification metrics outlining the model's accuracy on the hold-out test set.
  • False Positive Cost: A simulated financial impact metric showing how much money would have been lost if the system forcefully refused transactions instead of using smart escrow holds.
